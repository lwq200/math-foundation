## P0 严重视觉错误

### P0-1 全站 JSXGraph 交互画布空白

**问题描述**  
所有使用 JSXGraph 的交互组件（TangentExplorer、RiemannSum、MatrixTransform、GradientDescent、DotProduct、LimitEpsilonDelta、EpsNSequences、CDFExplorer、NormalDistSlider、KLDivergence、CLTSampling）在构建产物中均未成功渲染坐标轴、曲线、滑块等图形。DOM 探测显示 board 容器存在且尺寸正确（约 592×380-400px），但内部 `innerHTML === ""`，无 `<svg>`、无子元素。

**复现页面/条件**
- 浅色/深色模式均出现。
- 受影响的章节（仅列有截图的）：
  - 册03-单变量微积分/第01章-导数（TangentExplorer）
  - 册03-单变量微积分/第04章-积分与FTC（RiemannSum）
  - 册04-线性代数/第06章-特征值与特征向量（MatrixTransform）
  - 册04-线性代数/第01章-向量（DotProduct）
  - 册02-实数极限与连续/第04章-函数极限（LimitEpsilonDelta）
  - 册02-实数极限与连续/第03章-数列极限（EpsNSequences）
  - 册06-概率统计与信息/第03章-随机变量与分布（CDFExplorer）
  - 册06-概率统计与信息/第07章-常见分布族（NormalDistSlider）
  - 册06-概率统计与信息/第09章-互信息与KL散度（KLDivergence）
  - 册06-概率统计与信息/第05章-频率派统计（CLTSampling）
  - 册05-多元微积分与凸优化/第06章-无约束优化与梯度下降（GradientDescent）
- 移动端/桌面端均出现。

**根因（文件行）**
- 根本原因：构建产物未能将 `jsxgraph` 打入 client bundle，导致 `defineClientComponent` 懒加载失败，画布组件未 mount 或 mount 后无图形。
- 相关实现文件：
  - `.vitepress/theme/index.ts:46-57` 注册全部交互包装器。
  - 全部 `*Canvas.vue`（如 `.vitepress/theme/components/TangentCanvas.vue`、`MatrixTransformCanvas.vue` 等）使用 `defineClientComponent` + `await import('jsxgraph')` 懒加载。
  - `.vitepress/config.mts` 的构建/optimizeDeps 配置可能未将 `jsxgraph` 标记为 client-only 依赖或排除在 SSR 外。
- 历史佐证：`.vitepress/audit/report/diag-all.md` 已记录 `boardSvgCount: 0`、`svgShapeCount: 0` 等现象。

**修复建议**
1. 确认 `jsxgraph` 作为普通依赖被打包到 client bundle，避免 `defineClientComponent` 在 SSR 化产物中丢失懒加载资源。
2. 若必须懒加载，使用 `import('jsxgraph')` 时兼容 ESM default 导出：
   ```js
   const jsxg = await import('jsxgraph')
   const JXG = jsxg.default ?? jsxg.JXG
   ```
3. 在 `*Canvas.vue` 中增加加载占位与错误边界：
   - 加载中显示 spinner/skeleton；
   - 失败时显示 "交互图加载失败，请刷新" 并上报 `console.error`；
   - 避免用户看到空框。
4. 修复后使用 Playwright 全量回归 11 个组件的 `board.querySelector('svg')` 与形状数量。

### P0-2 首页 Hero 副标题深色模式不可读

**问题描述**  
首页 Hero 大标题 `.name` 在深色模式下为浅色，可读；但副标题 `.text`（即 `创世游戏系列 · 基础卷`）在深色模式下仍使用深绿渐变 `#2f6f4f → #1f5a3e` 并配合 `-webkit-text-fill-color: transparent`，导致在深背景 `#1b1b1f` 上对比度极低，肉眼难以辨认。

**复现页面/条件**
- 页面：`index.md` 首页。
- 条件：切换为深色模式（`html.dark`）。
- 桌面端、移动端均出现（见 `.vitepress/audit/report/ux/home-dark.png` 与 `home-dark-mobile.png`）。

**根因（文件行）**
- `.vitepress/theme/custom.css:86-99`：
  ```css
  .VPHero .text {
    background: linear-gradient(120deg, #2f6f4f 0%, #1f5a3e 100%);
    -webkit-background-clip: text;
    background-clip: text;
    -webkit-text-fill-color: transparent;
  }
  ```
  该规则未在 `.dark` 下覆盖，深色模式下深绿字+深背景导致不可见。

**修复建议**
在 `custom.css` 中补充深色模式覆盖：
```css
.dark .VPHero .text {
  background: linear-gradient(120deg, #5fd0a0 0%, #42b883 100%);
  -webkit-background-clip: text;
  background-clip: text;
}
```
修复后用 Playwright 重新截图 `home-dark.png` 确认可读。

## P1 明显体验问题

### P1-1 GraphCanvas.vue 使用 jsxgraph 1.13 不兼容的导入

**问题描述**  
`GraphCanvas.vue` 中直接读取 `import('jsxgraph').JXG`。但项目已确认 `jsxgraph@1.13.x` 为 ESM default 导出，`.JXG` 属性不存在，会导致 `Cannot read properties of undefined` 异常。该组件当前虽未被任何 `.md` 引用（`<VizFigure />` 也未使用），但属于潜伏的 P1。

**复现页面/条件**
- 任何未来使用 `<VizFigure />` 或 `<GraphCanvas />` 的页面。

**根因（文件行）**
- `.vitepress/theme/components/GraphCanvas.vue:22`：
  ```js
  const JXG = (await import('jsxgraph')).JXG
  ```

**修复建议**
改为项目其他组件已统一使用的兼容写法：
```js
const jsxg = await import('jsxgraph')
const JXG = jsxg.default ?? jsxg.JXG
```

## P2 打磨建议

### P2-1 JSXGraph `color` 配置使用 CSS var() 存在 SVG 属性兼容性隐患

**问题描述**  
全部 `*Canvas.vue` 在 `initBoard` 时传入：
```js
color: {
  axis: 'var(--vp-c-text-3)',
  grid: 'var(--vp-c-divider)',
  foreground: 'var(--vp-c-text-1)',
  border: 'var(--vp-c-divider)'
}
```
即便解决了 P0-1 的打包问题，JSXGraph 仍可能将上述值写入 SVG 的 `stroke`/`fill` 等 presentation attributes，而 CSS `var()` 在 SVG 属性中不受浏览器支持，会导致坐标轴/网格颜色失效或 fallback 为默认黑色。在深色模式下黑色坐标轴将不可见。

**复现页面/条件**
- 所有含 JSXGraph 组件的页面，P0-1 修复后必现。

**根因（文件行）**
- 各 `*Canvas.vue` 的 `initBoard` color 配置；
- `.vitepress/audit/接入说明.md:63` 记录此做法，但 Mermaid 已有 "不支持 CSS var()" 的历史教训。

**修复建议**
1. 在组件 mount 时通过 `getComputedStyle(document.documentElement).getPropertyValue('--vp-c-text-3')` 解析出实际颜色值再传入 JSXGraph。
2. 或改用 CSS 覆盖 `.jxgbox svg [stroke]` 样式，而非依赖 JSXGraph 内部设置。
3. 在浅色/深色模式下分别截图验证坐标轴、网格、标签颜色可读。

### P2-2 KaTeX 渲染 `␣`（U+2423）字符警告

**问题描述**  
构建日志出现多次：
```
No character metrics for '␣' in style Main-Regular
```
该字符（"open box"）常用于严格化走廊中表示空白/占位。KaTeX 字体缺少该字形，可能导致渲染为豆腐块或影响行高。

**复现页面/条件**
- 任何在 LaTeX 公式中使用 `␣` 的严格化走廊/证明块。

**根因**
- 内容中使用 U+2423 作为占位符，而 KaTeX 不支持。

**修复建议**
将 `␣` 替换为 KaTeX 原生可渲染方案，如 `\text{ }`、`\hspace{1em}`、或 CSS 伪元素可视化占位。

### P2-3 首页 SSR hydration mismatch

**问题描述**  
首页控制台出现：
```
Hydration completed but contains mismatches.
```
虽不阻塞功能，但可能导致首屏闪烁或布局抖动。

**复现页面/条件**
- `index.md` 首页，SSR 直出后客户端 hydrate。

**根因（文件行）**
- 可能与 `.VPHero .text` 的 `@supports (background-clip: text)` 渐变在服务端与客户端计算不一致有关；也可能与深色模式初始状态不同步有关。

**修复建议**
1. 检查 hero 渐变是否应在 `onMounted` 后通过客户端类名添加，避免 SSR/CSR 差异。
2. 修复 P0-2 时一并验证该警告是否消失。

### P2-4 Mermaid 深色模式反相滤镜为设计折中

**问题描述**  
当前深色模式通过 CSS 滤镜处理 Mermaid：
```css
.dark .mermaid svg { filter: invert(0.92) hue-rotate(180deg); }
```
该方案可工作，截图中 Mermaid 图表可读；但会反转所有语义色（如绿色变为近似品红），可能对依赖颜色区分的图例造成误导。

**复现页面/条件**
- 含 Mermaid 图表的章节，如册01-01、册02-02、册05-01 等。

**根因（文件行）**
- `.vitepress/theme/custom.css:236-247`。

**修复建议**
评估改为 Mermaid `theme: 'dark'` 并配置固定 `themeVariables`（不再使用 `var()`，已修复历史 bug），以获得更可控的深色主题色。

### P2-6 画布缺少加载态与错误态

**问题描述**  
`*Canvas.vue` 没有加载占位与错误提示。在 P0-1 修复前，用户看到的是与页面背景几乎无差异的空框；修复后若网络或脚本失败，仍可能看到空白。

**复现页面/条件**
- 所有含 JSXGraph 组件的页面。

**根因（文件行）**
- 各 `*Canvas.vue` 模板中仅渲染 board 容器，无 `v-if="loading"`/`v-if="error"` 分支。

**修复建议**
在每个 `*Canvas.vue` 中添加：
```vue
<div v-if="!ready" class="canvas-skeleton">交互图加载中…</div>
<div v-else-if="error" class="canvas-error">交互图加载失败</div>
<div v-else ref="boardEl" ... />
```
并设置合适的 `min-height` 与居中样式，避免布局抖动。
