# 第 06 章 · 计算模型——图灵机

> 本章从哪个问题出发：前面五章你在图论的"城市"里来回穿行——找最短路径、涂颜色、找一笔画的回路，每一样都有一套"算法"帮你算出答案。可你有没有想过一个问题：**"算法"到底凭什么算得出来？** 我们说"手工算一下""跑个程序""做个算法"，但"算"这个动作本身——它到底能算出什么，又有什么是算不出来的？如果有人给你一个"问题"，你凭什么判断它"可算"还是"不可算"？
> 推导到哪个结论：你会看见人类第一次把"算"这个动作本身，从"人脑里的一团直觉"钉成一个**机械装置**——图灵机。它只有纸带、读写头、状态和一张规则表，朴素得近乎寒酸，却能算尽你见过的所有算法。你会亲手写出它的形式定义（七元组），亲手跑一台判定"二进制奇数"的图灵机，把每一步"读→写→移→变状态"走完，还会理解那个著名的**Church–Turing 论题**——它凭什么是个"论题"而不是定理。
>
> 核心认知：**"能算"这个词，第一次有了精确到可以机械执行的答案：任何"直觉上可计算"的东西，都能被一台图灵机算出来。** 图灵机不是"某一种更快的机器"，而是"计算的底线"——像公理一样作为整座可计算性理论的地基。这一章是全册真正的转折点：从前五章的"具体怎么算"，跳到"什么算得出来"这个更根本的问题，下一章我们就要用这台机器，去问那个震撼数学界的问题——**有没有算不出来的东西？**

## 引子

我在老谟书房的白板上，画满了前面五章的图：最短路径的箭头、着色的色块、一笔画的回路。这些"算法"我都走熟了，可白板右下角留着一行字，是我今早进门时随手写下的：

"所有这些，到底是怎么'算'出来的？"

老谟走过来，看了那行字很久，忽然说："你这个问题问得好。我给你个简单的算法——**判断一个自然数是不是偶数**。你打算怎么'算'它？"

"……除 2 看余数？余 0 就是偶数。"

"对。可你'除 2'这个动作，是长什么样子的？你脑子里'算'的时候，究竟发生了哪几步？"

我愣住了。我会算，可我从没想过"算"这个动作本身拆开来是什么。就像一个人会说话，却从没想过声带是怎么振动的。

"更狠的是，"老谟盯着我，"如果我把'算偶数'这个算法，换成一个人**从没见过的、全新的**算法——你怎么保证，无论这个算法多复杂，你都'算得出来'？你怎么能确定，天底下不存在某一种算法，是你**根本算不出来的**？"

我看着白板上那些画得密密麻麻的图，第一次意识到：我手里有一堆"会算的方法"，却连"算"这个字到底是什么意思，都说不清。

## 对话引擎

### 第 1 轮：为什么需要"计算的模型"——算法 ≠ 具体程序

**老谟**："你先别急着造机器。我问你：'判断偶数'这个算法，你能用几种方式写出来？"

**造物主**："……我可以用自然语言说'除 2 看余数'，可以写一行伪代码 `n % 2 == 0`，可以画流程图，可以写 Python、C 语言……"

**老谟**："好，这些写法五花八门——语言、流程图、各种编程语言。**但它们是不是同一个算法？**"

**造物主**："是……同一个东西？只是'写法'不同。"

**老谟**："那问题来了。你说'它们是一个东西'，靠的是什么？如果两个写法一个在 Python 里、一个在 C 里，你凭什么说它们'算的是同一个算法'？"

**造物主**："……因为无论用什么语言写，跑起来的结果都一样？可我还没跑呢，而且跑的过程也千差万别。"

**老谟**："你摸到疼处了。**'算法'和'用某种语言写的程序'是两回事。** 算法是一个抽象的概念——'做这件事的一套确定步骤'；程序只是它在某种具体语言里的**一个化身**。如果每个化身都长得不一样，那'算法'本身到底是什么？它不依附于 Python、不依附于 C，它依附于……"

**造物主**："……依附于一个比所有语言都更底层、更简单的'算'的装置？一个只要你能在上面'算'，就说明你懂'算法'的装置？"

**老谟**："正是。**我们要的不是一台跑得快的机器，是一台'最简单、最朴素、却什么都能算'的机器**——用它钉死'算'这个动作本身。这样你才能问出真正要紧的问题：有没有东西，是连这台'万能机器'都算不出来的？"

### 📐 知识锚点：算法 vs 程序——"算"需要一个不依赖具体语言的基准

<blockquote>

【概念深挖】"算法"（algorithm）指**一套有限、确定、每一步都明确的步骤**；"程序"（program）是它**在某种具体计算语言/机器下的实现**。二者不能混为一谈：
- 同一个算法可以有无数个程序（不同语言、不同写法）；
- 不同语言看似"不同程序"，可能在抽象层面是**同一个算法**。

**难点**：正因为算法不依附于任何具体语言，若我们要研究"什么能被算出来"（可计算性），就必须有一个**不依赖具体语言的计算模型**——一个足够简单、简单到可以形式化写清楚、又足够强大、强大到能算任何算法的东西。**这个"基准模型"就是本章要造的图灵机。**

【工程实践】你在工程里天天遇到"算法 vs 实现"：一个排序算法（快排）在 Python、Java、C++ 里各有实现，还可能有多线程/分布式变体。**判断"这两个程序是不是同一个算法"、论证"这个优化没改变算法本质"，靠的正是算法层面的抽象——与具体语言解耦。** 图灵机就是给这种抽象一个最硬的锚。

</blockquote>

### 第 2 轮：图灵机的直觉——纸带、读写头、状态、规则表

**老谟**："现在我们要造那台'基准机器'。我不许你参考任何现代计算机——回到 1936 年，一个叫阿兰·图灵（Alan Turing）的年轻人，要回答'什么能被机械地算出来'，他造了一个想象出来的机器。你来跟我一起推：**一个人要'算'，最少需要什么？**"

**造物主**："……他得能'看'到当前的数字，得能'写'下结果，得知道'下一步该干嘛'……"

**老谟**："对。图灵把它拆成四个零件。**第一，一条无穷长的纸带**，分成一格一格，每格写一个符号（比如 0、1，或空白）。**第二，一个读写头**，对准当前那一格——它能读这一格是什么，能写一个新符号，能左移/右移一格。**第三，一个有限的状态**——机器现在'在哪个状态'，就好比人脑此刻'记着哪件事'。**第四，一张规则表**——每个状态 + 读到的符号，决定：写什么、往哪移、跳到哪个状态。"

**造物主**："……就这四个零件？没有内存、没有硬盘、没有 CPU 缓存？"

**老谟**："没有。**纸带就是它的'无穷内存'，读写头就是它的'存取单元'，状态就是它的'寄存器/大脑'，规则表就是它的'程序'。** 它寒酸，是因为图灵要的是'最少要多少，才够算'——**多一点都是多余的华丽，少一点都不够。**"

**造物主**："可它这么简单……真的能算'判断偶数'这种算法？"

**老谟**："先别急着怀疑。下一轮我们把它写成数学定义，再下一轮你亲手跑一遍，你就信了。"

### 📐 知识锚点：阿兰·图灵与 1936 年的"可计算数"

<blockquote>

【历史溯源】**阿兰·图灵（Alan Turing，1912–1954）** 在 **1936 年** 发表论文《论可计算数及其在判定问题上的应用》（*On Computable Numbers, with an Application to the Entscheidungsproblem*）。论文里他构造了一台"想象出的机器"（后称**图灵机**），用**一个机械装置**统一刻画"什么能被算出"。**同期，阿隆佐·丘奇（Alonzo Church）用"λ 演算"（lambda calculus）独立刻画了同一件事**——两人几乎同时、用不同工具得到了相同结论，即著名的 **Church–Turing 论题**。**要谨慎归因：图灵没有"发明计算机"**（电子计算机是多年后工程与数学共同推进的结果），他只是把"计算"这个抽象概念**第一次钉成了可机械执行的模型**。二战期间图灵在布莱切利园参与破译 Enigma 密码，那是他的工程贡献，但**不要把它和"发明图灵机"混为一谈**——图灵机是数学概念，破译是工程应用。

【工程实践】**图灵机 = 最简指令集 CPU 的思想**：纸带（内存）+ 读写头（内存访问单元）+ 状态（寄存器/程序计数器）+ 规则表（指令集）——这套结构在今天的 CPU、冯·诺依曼架构里仍能认出影子。"图灵完备"（Turing complete）是编程语言的**分水岭**：一个语言/系统若能力等价于图灵机（能算所有图灵可计算的函数），就能写任何算法；反之若不够（如某些只认正则表达式的查询语言），就注定有算不出来的算法。**判断一个新语言"够不够强"，就问它"图灵完备吗"。**

</blockquote>

### 第 3 轮：图灵机的严格定义——七元组，每步"读→写→移→变状态"

**老谟**："现在把直觉翻译成数学。一台**确定性图灵机**用七个东西（一个七元组）完全确定：\(M = (Q, \Sigma, \Gamma, \delta, q_0, q_{\mathrm{accept}}, q_{\mathrm{reject}})\)。你拆给我听，每个符号是什么？"

**造物主**："……\(Q\) 是状态的有限集合；\(\Sigma\) 是输入字母表（纸带上初始写的那类符号）；\(\Gamma\) 是纸带字母表（比 \(\Sigma\) 多一个空白符）；\(q_0\) 是起始状态；\(q_{\mathrm{accept}}\)、\(q_{\mathrm{reject}}\) 是接受/拒绝状态。"

**老谟**："好，剩下的关键是一个函数 **\(\delta\)——转移函数**。它是干什么的？"

**造物主**："……给定'当前状态 + 当前读到的符号'，它决定'写什么、往哪移、变成哪个状态'。所以 \(\delta\) 的定义域是 \(Q\times\Gamma\)，值域是 \(Q\times\Gamma\times\{L,R\}\)——L 是左移，R 是右移。**每一步，机器就是：读当前格 → 查 \(\delta\) 得到新符号、移动方向、新状态 → 写、移、换状态。**"

**老谟**："记住这个节奏：**读 → 写 → 移 → 变状态**。而且 \(\delta\) 对每个 (状态,符号) 给**恰好一个**结果——这就是'确定性'的意思：同一个局面，永远走同一条路，没有选择。至于为什么要'确定性'、要不要'非确定'，下一章我们专门讨论，先把这台确定性的机器跑熟。"

### 📐 知识锚点：七元组的形式骨架 + 语言/接受/停机预告

<blockquote>

【概念深挖】**确定性图灵机（Deterministic Turing Machine）**：一台图灵机是一个七元组
$$M=(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}),$$
其中：
- \(Q\)：有限状态集合（有限——因为人脑/规则表必须有限）；
- \(\Sigma\)：输入字母表（不含空白符 ␣）；
- \(\Gamma\)：纸带字母表，\(\Sigma\subseteq\Gamma\)，且空白符 ␣ \(\in\Gamma\)（纸带初始除输入外全为 ␣）；
- \(\delta : Q\times\Gamma\to Q\times\Gamma\times\{L,R\}\)：转移函数；
- \(q_0\in Q\)：起始状态；
- \(q_{\mathrm{accept}},q_{\mathrm{reject}}\in Q\)：接受/拒绝状态，且 \(q_{\mathrm{accept}}\neq q_{\mathrm{reject}}\)。

**每步动作**（一个"计算步"）：机器处于某状态 \(q\)，读写头对准某格读到符号 \(a\)；查 \(\delta(q,a)=(q',b,d)\)，于是：在该格**写** \(b\)，把读写头**移**动一格（\(d=L\) 左移，\(d=R\) 右移），进入**状态** \(q'\)。

**停机约定**：到达 \(q_{\mathrm{accept}}\) 或 \(q_{\mathrm{reject}}\)，机器**停机**（不再转移），分别表示"接受/拒绝输入"。语言 \(L(M)\) = 所有"从 \(q_0\) 出发、输入写在纸带上、最终停机在 \(q_{\mathrm{accept}}\)"的输入串的集合。

</blockquote>

### 第 4 轮：跑一台图灵机——"二进制串含 1 吗"

**老谟**："纸上谈兵到此为止。我们造一台真的机器：**判定输入二进制串是否至少含一个 '1'**（含则接受，不含则拒绝）。你先想，它要怎么'扫描'？"

**造物主**："……从头往右一格一格扫，遇到 '1' 就说明'有了'，可以直接接受；如果一直扫到纸带末尾（空白）都没见着 '1'，就拒绝。"

**老谟**："好，那状态怎么设？"

**造物主**："一个状态 \(q_0\) 就够了，加上 \(q_{\mathrm{accept}}\)、\(q_{\mathrm{reject}}\)。规则表：**在 \(q_0\)，读到 0 → 写 0、右移、留在 \(q_0\)（继续找）；读到 1 → 进 \(q_{\mathrm{accept}}\)（找到了，接受）；读到 ␣ → 进 \(q_{\mathrm{reject}}\)（走到底都没找到，拒绝）。**"

**老谟**："好。现在你亲手在纸上跑输入 **0010**。把每一步的'状态、读写头对准哪个位置、当前纸带长什么样'都写下来。"

**造物主**："……第 0 步：状态 \(q_0\)，纸带 `0 0 1 0 ␣ ␣…`，头对准第 1 格（最左的 0）。读 0 → 写 0、右移、留 \(q_0\)。第 1 步：头对准第 2 格 '0'，读 0 → 右移。第 2 步：头对准第 3 格 '1'，读 1 → 进 \(q_{\mathrm{accept}}\)。**第 3 步：停机接受！**"

**老谟**："跑通了。那输入 **000** 呢？"

**造物主**："第 0、1、2 步一直右移扫三个 0，第 3 步读到第 4 格的 ␣ → 进 \(q_{\mathrm{reject}}\)，**停机拒绝**。对，000 里确实没有 1。"

### 📐 知识锚点：跑一台机器的完整"轨迹"——configuration（格局）

<blockquote>

【概念深挖】一台机器"跑"到某时刻的完整快照叫一个**格局（configuration）**。由于机器的一切状态由三样决定——**当前状态、纸带内容、读写头位置**——一个格局记作三元组 \((q,\, \text{当前纸带}, \, \text{头的位置})\)。比如上面"含 1 机"跑 0010，可用记号 \(\underline{q_0}\,0010\) 表示"状态 \(q_0\)，头对准第一个符号 0"（在状态下划线代表头位置，纸带只写出含输入那一段）。

**一次转移 = 一个格局变到下一个格局**：\((q, w\underline{a}u) \vdash (q', w b \underline{c}u)\) 表示"在 \(q\) 读到 \(a\)，写成 \(b\)，右移一格到 \(c\)，变 \(q'\)"。**完整运行轨迹 = 格局序列**，从初始格局 \((q_0,\underline{w})\) 一直走到停机格局。**"接受/拒绝" = 这条格局序列的终点停在 \(q_{\mathrm{accept}}\) 或 \(q_{\mathrm{reject}}\)。**

【工程实践】**格局 = 程序的运行状态**（寄存器值 + 内存内容 + 程序计数器）。调试器里看到的"断点处的完整现场"，就是工程版的"格局"；"一步步单步执行"就是"逐个格局走"。**把程序当格局序列来走，正是编译器/解释器/调试器的底层思维。**

</blockquote>

### 第 5 轮：判定 vs 计算——语言、接受、停机

**老谟**："我们刚造了两台机器（含 1 机、以及下一轮要造的奇数机）。它们做的是同一件事：**对每个输入，给一个'接受/拒绝'的答案。** 这类问题叫**判定问题（decision problem）**。你给它串，它答'是'或'否'。现在我要给你一个更本质的抽象——**语言（language）**。"

**造物主**："语言？不是'编程语言'那个语言吧？"

**老谟**："是形式语言：**某组符号（字母表）上所有串里，满足某个条件的那一堆。** 比如'所有含 1 的二进制串'就是一个语言——**一台判定机'接受'的输入串的全体，恰好就是它对应的语言。** 判定一个输入'在不在这个语言里'，等价于'机器接受不接受它'。"

**造物主**："……所以'判定一个问题' = '判定一个串属于某个语言' = '这台机器停不停在接受状态'。那'停机'呢？"

**老谟**："**停机 = 机器跑完了、给出最终答案。** 我们设计的这两台机器，对任何输入**必然停机**（扫描是有限的）。可你要小心：**不是每台机器对每个输入都停机**——有的机器可能永远停不下来（一直移、永远不停）。**'能停机并给出答案'和'停不下来'的差别，是下一章那个震撼问题的命根子，你先记住这个区分。**"

---

### 📐 知识锚点：判定问题、语言、可判定性——三块基石

<blockquote>

【概念深挖】
- **判定问题**：给一个输入串，要求回答"是/否"。一台图灵机把每个输入"接受（是）或拒绝（否）"。
- **语言**：字母表 \(\Sigma\) 上的**语言**是 \(\Sigma^*\)（所有有限串的集合）的任意子集。判定机 \(M\) **接受**的语言记作 \(L(M)=\{w \mid M \text{ 在输入 } w \text{ 停机于 } q_{\mathrm{accept}}\}\)。
- **可判定（decidable）**：若**存在**一台图灵机 \(M\)，对**每个输入都能停机**，且正确回答"属于 \(L\) 否"（属于→接受，不属于→拒绝），则称语言 \(L\) **可判定**。**"可判定" = "有一个算法能判断每个输入"**——这正是"能算"的精确化。
- **可计算函数**：一台图灵机，若对每个输入 \(w\) 停机时纸带上留下某输出 \(f(w)\)，则它**计算**了函数 \(f\)。函数可计算 = 存在图灵机算它。

**关键区分（下一章的地雷）**：**"可判定"要求对每个输入都停机**。如果一台机器"接受某些输入、但在别的输入上永远不停机"，那它**不算**"判定"这个语言——它可能"半判定"（只在'是'时停机接受），但没给出"否"的完整答案。**"总是停机且正确"才是可判定。** 下一章我们会看到：有的语言，任何机器都无法同时满足"对每个输入停机 + 正确回答"。

【工程实践】**判定问题 = 布尔函数/谓词**：`is_even(n)`、`contains_1(s)` 都是判定问题。**语言 = 数据子集/合法输入集**：一个 API 校验函数返回"合法/非法"，就是判定"输入是否属于'合法语言'"。"可判定"在工程里就是"存在一个算法能对所有输入给出确定答案"——**如果你论证某问题"不可判定"，等于宣布'没有任何算法能对所有输入给出答案'，这是比'很难/很慢'严重得多的结论。**

</blockquote>

### 第 6 轮：Church–Turing 论题——为什么它是"论题"不是定理

**老谟**："我们现在手里有一个具体的机器了。可我要抛给你一句极其重要的话：**'任何直觉上可计算（可判定）的函数，都能用图灵机算出来。'** 你看这句话，能不能被'证明'？"

**造物主**："……'直觉上可计算'这个说法，本身就不是一个数学对象。**我没法证明一句话，因为它的主语'直觉可计算'根本没被定义。**"

**老谟**："你答到点子上了。这就是为什么它叫 **Church–Turing 论题（thesis）**，而不是定理——**定理要在固定的公理/定义下证明；可'直觉上可计算'这个词，没法放进形式系统，所以这个命题无法在数学内部证明。** 它更像一条**经验定律**："

**造物主**："……那我凭什么信它？"

**老谟**："因为它**从未被推翻**。八十多年了，人们提出过无数种'计算模型'——λ 演算、递归函数、图灵机、寄存器机、甚至现代编程语言——**所有被认真提出的、直觉可计算的东西，都能被图灵机算出来。** 大家找到一个又一个'更强的机器'，最后发现**没有一台比图灵机更强**。证据如山，所以它被当作可计算性理论的地基——像公理一样被接受。"

**造物主**："……那万一明天有人找到一个图灵机算不了、但直觉能算的东西呢？"

**老谟**："那我们的整座大厦就要重盖。但八十年没人做到——**所以现在，'能算'和'图灵机能算'，在我们这本书里就是同一个意思。** 它的价值在于：它给了'算不出来'一个可以下手的精确定义——**'图灵机也算不出来' = '真的算不出来'。** 下一章我们就用这个，去证那个震撼世界的结果。"

### 📐 知识锚点：Church–Turing 论题——地基式信念，逐条拆解

<blockquote>

【概念深挖】**Church–Turing 论题**：**任何"直觉上可计算"的函数（或可判定的语言），都可被某台图灵机计算（判定）。**
- **为什么是"论题"而非"定理"**："直觉上可计算"没有形式定义，命题无法在形式系统内表述，因此不可证。这是它与"定理"的根本区别。
- **证据**：① 多个独立模型（λ 演算、递归函数、图灵机）殊途同归；② 所有提出的计算模型都彼此等价、且都不超过图灵机；③ 从未有人构造出"直觉可算但图灵机算不了"的例子。
- **作用**：它把"算不出来"转译成"图灵机也算不出来"——**给可计算性一个可着手的形式定义**。本书从此约定"可计算 = 图灵可计算"。

【历史溯源】1936 年，**图灵**（图灵机）与 **丘奇**（λ 演算）**独立**提出刻画"可计算"的方案，随后证明二者等价。**"Church–Turing 论题"这一命名本身是后人的事**——归因要谨慎：图灵与丘奇分别给出的是"模型"，"论题"作为一条信念被广泛接受，是数学共同体后续共识的产物。**不夸大**：没有人"证明"了它；它是可计算性理论被接受的地基。

【工程实践】**"图灵完备"作为分水岭**：一个编程语言/系统若能力等价于图灵机（能表达所有图灵可计算函数），称"图灵完备"（如 C、Python、λ 演算、甚至一些游戏里的红石电路/纸牌系统）。**"这个系统图灵完备吗"是在问"它能表达任意算法吗"**——图灵完备的系统能算的"上限"是相同的（都到图灵机这个天花板）；不够图灵完备的系统（如纯正则语言）则有明确的、表达不了的东西。**这是你判断一个工具"够不够强"最锋利的一把尺。**

</blockquote>

### 第 7 轮：变体都等价——为下一章的"停机问题"铺路

**老谟**："你可能觉得这机器太寒酸：一条纸带、一个头、确定性的、还慢得离谱。**我告诉你一个反直觉的事实：把图灵机改造成'多纸带''双向纸带''非确定'等各种花样，算出来的东西和原来这台，完全一样。**"

**造物主**："……什么？！多纸带、非确定性，听起来强大得多，结果和这条单纸带的是一回事？"

**老谟**："对。**这些'变体'都能被原版图灵机模拟**——多纸带可以'编码'到一条纸带上，非确定性可以用'广度优先搜索所有分支'来模拟。**'能算的集合'没变，变的只是'快慢'和'方便'。** 这正好印证了 Church–Turing 论题背后那股力量：计算的'天花板'只有一个，所有变体都碰在同一面墙上。"

**造物主**："……那为什么还要提这些变体？"

**老谟**："因为它们好用，也因为它们**不会改变'算得出来吗'这个问题的答案**。这给我们一个巨大的便利：**研究'能不能算'时，随便挑一个最顺手的模型，答案都一样。** 下一章，我们要问'有没有图灵机算不出来的问题'——到那时，这些变体等价性就是我们的底气：**无论把机器改得多花哨，都躲不过那个'算不出来'的墙。**"

### 📐 知识锚点：图灵机的变体——花哨归花哨，等价是真身

<blockquote>

【概念深挖】常见的图灵机**变体**及其与原版的等价性（均"能算的集合相同"）：
- **多纸带图灵机**（k 条纸带、k 个读写头）：可被单纸带机**模拟**（把 k 条纸带"压"进一条，用记号/标记区分并跟踪各自读写头位置）。
- **双向纸带**：原版纸带已可任意左右移动，双向与否不改变能力（只是约定差别）。
- **非确定性图灵机（NTM）**：转移关系允许"同一 (状态,符号) 有多个后继选择"。可被确定性图灵机**模拟**——用"广度优先"探索所有可能的分支（或用三段式"猜测→验证"技巧）。**关键是：非确定性和确定性图灵机接受的语言集合相同**（但可能快很多——这恰恰是第 8 章 P vs NP 的伏笔！）。

**为什么等价性重要**：因为我们要问"什么算得出来"，而**这些变体都算得同样多**，所以结论对哪个模型都成立。**这也支撑 Church–Turing 论题**：不是某个具体机器强大，而是"可计算"这个概念本身坚固。

【工程实践】**等价变体在工程里的对应**：同一算法可以写成单线程、多线程、流式、递归、迭代——**"能算的东西"一样，只是实现策略不同**（这正是"同一算法不同程序"的具体化）。**非确定性 = "并行/分支探索"的抽象**：工程里"猜一个解再验证"、剪枝搜索、回溯，都暗含非确定性的思想；而"把它模拟成确定性的"，就是"把分支展开成搜索"。

</blockquote>

## 严格化走廊

> 位置说明：对话负责"直觉"——为什么需要计算模型、图灵机为什么长这样、变体为什么等价。本走廊负责"严谨"——把图灵机钉成可复写的形式定义（七元组、格局），给出本章的核心定理（**确定性：每步转移唯一**，以及**图灵机可模拟有限自动机**的构造），并亲手走完"二进制奇数判定机"的**完整格局序列**逐行验证。红线 1 的硬要求：每个证明标"证明类型 + 每一步依据"，不用"显然"。

### 定义：图灵机（七元组）——精确表述

> 一台**确定性图灵机**是一个七元组
> $$M=(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}),$$
> 其中：
> - \(Q\) 是**有限**非空状态集合；
> - \(\Sigma\) 是**输入字母表**，不含空白符 ␣；
> - \(\Gamma\) 是**纸带字母表**，且 \(\Sigma\subseteq\Gamma\)，␣ \(\in\Gamma\setminus\Sigma\)；
> - \(\delta : (Q\setminus\{q_{\mathrm{accept}},q_{\mathrm{reject}}\})\times\Gamma \to Q\times\Gamma\times\{L,R\}\) 是**转移函数**；
> - \(q_0\in Q\) 是起始状态；
> - \(q_{\mathrm{accept}},q_{\mathrm{reject}}\in Q\) 是**接受/拒绝**状态，\(q_{\mathrm{accept}}\neq q_{\mathrm{reject}}\)。

**约定说明**：\(\delta\) 的定义域**排除了接受/拒绝状态**——这是"停机"的形式化：到达 \(q_{\mathrm{accept}}\)/\(q_{\mathrm{reject}}\) 后机器不再动作（没有下一跳），即**停机**。纸带为**无穷**（两端无限），除输入段外全为 ␣。**"计算"在此的定义即"从初始格局出发，反复执行转移，直到停机（或永不停止）"**——这和整本书"先约定后定理"的主线一致：图灵机是我们选定的计算约定。

### 定义：格局（configuration）——机器的一格快照

> 一台图灵机在某个时刻的**格局**是三元组 \((q, u\,a\,v, i)\)，含义为：当前状态 \(q\)；纸带上内容（含输入段与有限个非空白扩展）为 \(\ldots u\,a\,v\ldots\)；读写头正对准符号 \(a\) 所在的那一格；\(i\) 记该格位置（有时直接用下划线标注头位置：\(u\,\underline{a}\,v\)）。

**从格局到格局**：若 \(\delta(q,a)=(q',b,d)\)，则
- \(d=R\)（右移）时：格局从 \((q,u\underline{a}v)\) 变为 \((q',u\,b\,\underline{v_{\text{首}}})\)（写在 \(a\) 处得 \(b\)，头右移到 \(v\) 的第一个符号）；
- \(d=L\)（左移）时：变为 \((q',u_{\text{末}}\underline{\,b\,}v)\)（写在 \(a\) 处得 \(b\)，头左移到 \(u\) 的最后一个符号）。

**初始格局**：输入串 \(w\) 写在纸带最左段，头对准 \(w\) 的第一个符号，状态 \(q_0\)。**停机格局**：状态为 \(q_{\mathrm{accept}}\) 或 \(q_{\mathrm{reject}}\)。**语言** \(L(M)=\{w\in\Sigma^* \mid M\text{ 从初始格局出发，最终停在 }q_{\mathrm{accept}}\}\)。

> **证明类型标注**：本章核心证明共两处——**定理 1（每步转移唯一）用直接证明**（对"转移函数是函数"的形式论证）；**定理 2（图灵机可模拟有限自动机）用构造性证明**（显式构造出模拟任意给定有限自动机的图灵机，并验证其行为一致）。后者正是蓝图第 6 章必含证明。
>
> **关于对话**：对话第 3 轮把七元组拆给造物主推，靠的是"引导式推导"（让他自己认出每个符号的职责）；**形式化定义与格局序列在本走廊**。对话负责"为什么会想到七元组/格局"，走廊负责"怎么把它写标准"——与前五章及册 01–06 口径一致。

### 定理 1（确定性：每步转移唯一）

**前提**：\(M=(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}})\) 是确定性图灵机，\(M\) 处于非停机状态 \(q\) 且读写头读到符号 \(a\)。

**结论**：机器下一步的动作**唯一确定**（要写的新符号、移动方向、进入的新状态，都只有一个）。

**证明类型**：直接证明（用"转移函数是单值函数"这一形式性质）。

**证明**：
- 第 1 步：**回忆转移函数定义**：\(\delta : (Q\setminus\{q_{\mathrm{accept}},q_{\mathrm{reject}}\})\times\Gamma \to Q\times\Gamma\times\{L,R\}\)。（依据：图灵机定义——\(\delta\) 是定义在"非停机状态×符号"上的函数。）
- 第 2 步：**"函数"即"单值映射"**：对定义域中每个元素 \((q,a)\)，\(\delta(q,a)\) 是值域 \(Q\times\Gamma\times\{L,R\}\) 中的**恰好一个**元素（而不是一个集合）。这是"函数（function）"这一概念的定义性质：每个输入恰好对应一个输出。（依据：映射/函数的定义——单值性。）
- 第 3 步：**当前局面落在定义域内**：机器处于非停机状态 \(q\)（非停机，故 \((q,a)\) 属于 \(\delta\) 的定义域），头读到符号 \(a\in\Gamma\)。（依据：前提 + \(\Gamma\) 是纸带字母表。）
- 第 4 步：**结论**：由第 2、3 步，\(\delta(q,a)=(q',b,d)\) 唯一确定，故"写 \(b\)、按 \(d\) 移动、进 \(q'\)"唯一确定。∎

> **依据标注**：步 1 用"定义"（\(\delta\) 的签名）；步 2 用"函数的单值性"（这是"确定性"的来源——同一输入只有一种结局，这正是图灵机区别于"非确定"的本质）；步 3 用"前提+定义域"；步 4 收束。**读法**：这个定理的力气全在步 2——**"确定性"不是机器的物理性质，是"转移函数是函数（单值）"这一约定的直接推论**。若把 \(\delta\) 改成"转移关系"（允许一对多），就得到非确定性图灵机——那是第 8 章的伏笔。

### 定理 2（图灵机可模拟有限自动机）——构造性证明

**前提**：任意给定一个**确定性有限自动机（DFA）** \(A=(Q_A,\Sigma_A,\delta_A,q_{0A},F_A)\)，其中 \(\delta_A:Q_A\times\Sigma_A\to Q_A\) 是状态转移函数，\(F_A\subseteq Q_A\) 是接受状态集合。（DFA 是"有限记忆"的自动机：只认当前状态和当前读到的符号，无外部存储。）

**结论**：存在一台图灵机 \(M\)，使得对每个输入串 \(w\in\Sigma_A^*\)：\(M\) 接受 \(w\) ⟺ DFA \(A\) 接受 \(w\)（即 \(L(M)=L(A)\)）。

**证明类型**：构造性证明（显式构造 \(M\) 并验证）。

**证明**：
- 第 1 步：**构造 \(M\) 的状态集**：令 \(M\) 的状态集 \(Q = Q_A \cup \{q_{\mathrm{accept}},q_{\mathrm{reject}}\}\)，输入字母表 \(\Sigma=\Sigma_A\)，纸带字母表 \(\Gamma=\Sigma_A\cup\{\square\}\)，起始状态 \(q_0=q_{0A}\)。（依据：模拟策略——用"当前状态"承载 DFA 的记忆，用纸带只承载输入。）
- 第 2 步：**定义转移函数 \(\delta\)**：对每个 \(q\in Q_A\)、每个 \(a\in\Sigma_A\)，令
  $$\delta(q,a)=(q', a, R),\quad\text{其中 } q'=\delta_A(q,a).$$
  含义：**读到输入符号 \(a\) 时，\(M\) 把 DFA 的转移 \(\delta_A(q,a)=q'\) 复刻过来——把当前状态改成 \(q'\)、符号原样写回、向右移一格继续读下一个输入符号**。（依据：模拟 DFA 的"从左到右扫描输入、每步换状态"的行为。）
- 第 3 步：**定义边界（读到空白）的动作**：对每个 \(q\in Q_A\)，令
  - 若 \(q\in F_A\)（DFA 的接受状态）：\(\delta(q,\square)=(q_{\mathrm{accept}},\square,R)\)；
  - 若 \(q\notin F_A\)：\(\delta(q,\square)=(q_{\mathrm{reject}},\square,R)\)。
  含义：**当读写头扫过整个输入、读到第一个空白 ␣ 时，输入已读完**；此时若 DFA 停在接受状态 \(F_A\) 就接受，否则拒绝。（依据：DFA 的接受定义——读完整个输入、结束状态在 \(F_A\) 中才接受。）
- 第 4 步：**验证 \(L(M)\subseteq L(A)\)**：若 \(M\) 接受 \(w\)，则 \(M\) 读完全部输入后在 \(q_{\mathrm{accept}}\) 停机；由第 2、3 步构造，这只在 DFA 读完整串后停于 \(F_A\) 时发生，故 DFA \(A\) 接受 \(w\)。（依据：第 2、3 步的定义——\(M\) 的接受由"DFA 终态 ∈ \(F_A\)"触发。）
- 第 5 步：**验证 \(L(A)\subseteq L(M)\)**：若 DFA \(A\) 接受 \(w\)，则按 \(\delta_A\) 逐步转移，读完 \(w\) 后停在某个 \(q\in F_A\)；由第 2、3 步，\(M\) 复刻每一步转移，读到 ␣ 时停在 \(q_{\mathrm{accept}}\)，故 \(M\) 接受 \(w\)。（依据：第 2 步复刻转移 + 第 3 步接受触发。）
- 第 6 步：**由第 4、5 步得 \(L(M)=L(A)\)**。∎

> **依据标注**：步 1、2、3 是"构造"（显式给出 \(M\) 的七元组）；步 4、5 是"验证"（双向包含，DFA 接受 ⟺ M 接受）；步 6 收束。**读法**：这个构造的精髓是——**DFA 只有"有限状态"这个记忆，图灵机把"状态"原封不动搬过来，再把纸带当成"读输入"的带子**，于是有限自动机能做的，图灵机全能做。**这印证了"图灵机是最强大的模型之一"：连有限自动机都能模拟**。注意：图灵机比 DFA 强得多（多了纸带这个无限存储），模拟只是"弱模型 ⊂ 强模型"的一例。

### 例子（亲算）：二进制奇数判定机——完整格局序列逐行验证

**问题**：构造一台判定"二进制串表示奇数"的图灵机，即接受所有以 '1' 结尾的二进制串（如 `1011`、`1`），拒绝以 '0' 结尾的（如 `1010`）。（约定：非空输入，最右符号即个位；二进制奇数个位必为 1。）

**机器设计**（三个状态 + 规则表）：
- 状态集 \(Q=\{q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}\}\)，\(\Sigma=\{0,1\}\)，\(\Gamma=\{0,1,\square\}\)，起始 \(q_0\)。
- 转移表：
  - \(q_0\)：读 0 → 写 0、右移、留 \(q_0\)（继续扫描）；
  - \(q_0\)：读 1 → 写 1、右移、留 \(q_0\)；
  - \(q_0\)：读 ␣ → 写 ␣、**左移**、进 \(q_1\)（走到最右非空格，回退看个位）；
  - \(q_1\)：读 1 → 写 1、右移、进 \(q_{\mathrm{accept}}\)（个位是 1 → 奇数，接受）；
  - \(q_1\)：读 0 → 写 0、右移、进 \(q_{\mathrm{reject}}\)（个位是 0 → 偶数，拒绝）。

**逻辑核验**：二进制数奇偶**只由个位（最右输入符号，即最低位）决定**——末尾是 1 即奇数，末尾是 0 即偶数。机器扫描到最右，回退看个位：是 1 接受、是 0 拒绝。**先理解设计，再走轨迹。**

**输入 `1011`**（二进制 11，奇数，应接受），完整格局序列（用下划线标头位置）：

| 步 | 状态 | 纸带（头位置用下划线） | 依据 |
|----|------|------------------------|------|
| 初始 | \(q_0\) | \(\underline{1}\,0\,1\,1\,\square\) | 头对准首字符，状态 \(q_0\)（初始格局） |
| 1 | \(q_0\) | \(1\,\underline{0}\,1\,1\,\square\) | 读 1→写 1、右移、留 \(q_0\) |
| 2 | \(q_0\) | \(1\,0\,\underline{1}\,1\,\square\) | 读 0→写 0、右移、留 \(q_0\) |
| 3 | \(q_0\) | \(1\,0\,1\,\underline{1}\,\square\) | 读 1→写 1、右移、留 \(q_0\) |
| 4 | \(q_0\) | \(1\,0\,1\,1\,\underline{\square}\) | 读 1→写 1、右移、留 \(q_0\) |
| 5 | \(q_1\) | \(1\,0\,1\,\underline{1}\,\square\) | 读 ␣→写 ␣、**左移**、进 \(q_1\) |
| 6 | \(q_{\mathrm{accept}}\) | \(1\,0\,1\,1\,\underline{\square}\) | 读 1（个位）→写 1、右移、进 \(q_{\mathrm{accept}}\) |

**第 6 步：停机接受**。反向验证：二进制 `1011` = \(8+0+2+1=11\)，11 是奇数 ✓；机器接受，正确。

**输入 `1010`**（二进制 10，偶数，应拒绝），完整格局序列：

| 步 | 状态 | 纸带 | 依据 |
|----|------|------|------|
| 初始 | \(q_0\) | \(\underline{1}\,0\,1\,0\,\square\) | 初始格局 |
| 1 | \(q_0\) | \(1\,\underline{0}\,1\,0\,\square\) | 读 1→右移 |
| 2 | \(q_0\) | \(1\,0\,\underline{1}\,0\,\square\) | 读 0→右移 |
| 3 | \(q_0\) | \(1\,0\,1\,\underline{0}\,\square\) | 读 1→右移 |
| 4 | \(q_0\) | \(1\,0\,1\,0\,\underline{\square}\) | 读 0→右移 |
| 5 | \(q_1\) | \(1\,0\,1\,\underline{0}\,\square\) | 读 ␣→左移、进 \(q_1\) |
| 6 | \(q_{\mathrm{reject}}\) | \(1\,0\,1\,0\,\underline{\square}\) | 读 0（个位）→进 \(q_{\mathrm{reject}}\) |

**第 6 步：停机拒绝**。反向验证：二进制 `1010` = \(8+0+2+0=10\)，10 是偶数 ✓；机器拒绝，正确。

> **核算记录**：① 两例均在第 5 步"读到 ␣ 左移"进入 \(q_1\)，头落在最右输入符号（个位）上——用输入长度 4 手工核对，4 个符号扫描后第 5 格是 ␣，左移即回到第 4 格（个位），正确；② `1011` 个位 1 → 接受，`1010` 个位 0 → 拒绝，均与"末尾 1 奇、0 偶"的奇偶判定一致；③ 转移表每个 (状态,符号) 恰好一个动作，符合定理 1 的确定性。**反向验证通过。**

### 反例/边界：形式定义 vs 直觉的差距

1. **图灵机可无限跑不停**：形式定义允许机器"永远不停机"（无休止移动/改写）。**直觉"算法必然结束"在这里不成立**——是否存在"对每个输入都停机"的机器，恰恰是"可判定"与"不可判定"的分界（下一章的核心）。
2. **纸带"无穷"是理想化**：真实计算机内存有限，图灵机纸带无限。**图灵机是"如果内存无限够用，能算到什么程度"的极限模型**——它刻画的是"算法上能不能"，不是"工程上内存够不够"。
3. **转移函数必须定义在非停机状态上**：若把 \(q_{\mathrm{accept}}\)/\(q_{\mathrm{reject}}\) 也放进 \(\delta\) 定义域，机器就不会"停"而是继续跑——**"停机"是靠"停机状态无转移"约定出来的，不是机器的物理属性**。
4. **"可判定"要求对每个输入都停机且正确**：一台只在"接受"时停机、在"拒绝"时永不停止的机器，**不算**判定该语言（只是半判定）。**"总是停机"是"可判定"里最硬的一条。**
5. **变体等价不等于变体没用**：非确定图灵机"能算的集合"与确定性相同，但**可能快得多**——"算得出"和"算得快"是两回事，这正是第 8 章 P vs NP 的分界。

## 知识点总结

### 知识点（本章推出的核心概念）

- **图灵机（七元组）**：\(M=(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}})\)。四个零件：纸带（无限内存）+ 读写头（存取单元）+ 有限状态 + 转移函数（规则表=程序）。**每步"读→写→移→变状态"。**
- **转移函数** \(\delta:Q\times\Gamma\to Q\times\Gamma\times\{L,R\}\)：对每个 (非停机状态, 符号) 给**恰好一个**结果——**确定性**的来源。
- **格局（configuration）**：\((q,\text{纸带},\text{头位置})\)，一次转移=一个格局变到下一个；**运行轨迹 = 格局序列**。
- **语言**：\(\Sigma^*\) 的子集；\(L(M)\) = \(M\) 接受的串的集合。
- **可判定（decidable）**：存在一台图灵机，**对每个输入都停机**且正确回答"属于 \(L\) 否"。**"可判定"="能算"**。
- **可计算函数**：存在图灵机对每个输入停机时输出对应值。
- **Church–Turing 论题**：直觉可计算 = 图灵可计算。**是"论题"不是定理**（主语无法形式定义），从未被推翻，作为地基被接受。
- **变体等价**：多纸带、双向、非确定图灵机与原版**接受的语言集合相同**。

### 历史结论（本章涉及的史料）

- **图灵（1936）**：论文《论可计算数及其在判定问题上的应用》，构造图灵机刻画"可计算"。
- **丘奇（同期）**：λ 演算独立刻画同一件事；**二人独立发现、殊途同归**。
- **Church–Turing 论题**：命名与确立是共同体后续共识；**从未被证明，也从未被推翻**。
- **谨慎归因**：图灵**没有"发明计算机"**——图灵机是数学概念，电子计算机是工程与数学多年共同推进的产物；二战破译 Enigma 是工程应用，与图灵机发明是两回事。

### 工程实践结论（本章知识在真实工程里怎么用）

- **图灵机 = 最简指令集 CPU 的思想**：内存（纸带）+ 存取单元（读写头）+ 状态（寄存器）+ 规则表（指令集）。
- **"图灵完备"是分水岭**：语言/系统能力等价于图灵机就能写任意算法；不够图灵完备则有明确的表达上限。**判断工具"够不够强"就问"图灵完备吗"。**
- **格局 = 调试现场**：寄存器+内存+程序计数器，单步执行就是逐个格局走。
- **判定问题 = 布尔函数**；**"不可判定" = "没有任何算法能对所有输入给答案"**——这是远比"难/慢"严重的结论。

## 计算训练场

> 位置说明：对话负责"为什么需要图灵机、它为什么长这样"，这里负责"怎么亲手造机器、怎么走轨迹"。下面三题**必须动笔**，每题 10 分钟以上，先自己写再对答案。**难度递进：易→中→难。** 重点：① 设计状态/转移表；② 亲手走完整格局序列；③ 体会"什么不是图灵机可算"的直觉。

### 题 1（易）：设计判定"串含 1"的图灵机——完整状态表

**题干**：老谟让造物主设计一台图灵机，判定输入二进制串是否**至少含一个 '1'**。写出：状态集、纸带字母表、完整转移表，并解释每个规则的作用。然后亲手走输入 `0010` 的格局序列。

**完整解答**：

- 状态集：\(Q=\{q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}\}\)；输入字母表 \(\Sigma=\{0,1\}\)；纸带字母表 \(\Gamma=\{0,1,\square\}\)；起始 \(q_0\)。
- **转移表**：
  | 当前状态 | 读到的符号 | 写 | 移动 | 下一状态 | 作用 |
  |----------|-----------|----|------|----------|------|
  | \(q_0\) | 0 | 0 | R | \(q_0\) | 不是 1，继续右扫 |
  | \(q_0\) | 1 | 1 | R | \(q_{\mathrm{accept}}\) | 找到 1，接受 |
  | \(q_0\) | ␣ | ␣ | R | \(q_{\mathrm{reject}}\) | 走到底没 1，拒绝 |
- **逻辑**：从最左向右扫，碰到 1 立即接受；碰到空白（输入结束）拒绝。

**输入 `0010` 的格局序列**：
| 步 | 状态 | 纸带 | 依据 |
|----|------|------|------|
| 初始 | \(q_0\) | \(\underline{0}\,0\,1\,0\,\square\) | 初始格局 |
| 1 | \(q_0\) | \(0\,\underline{0}\,1\,0\,\square\) | 读 0→右移 |
| 2 | \(q_0\) | \(0\,0\,\underline{1}\,0\,\square\) | 读 0→右移 |
| 3 | \(q_{\mathrm{accept}}\) | \(0\,0\,1\,\underline{0}\,\square\) | 读 1→进接受 |

**第 3 步停机接受**（`0010` 含 1 ✓）。

**常见错误**：① 状态设太多/太少（一个扫描状态足够，接受/拒绝各一）；② 忘记处理空白 ␣（否则扫描到输入末尾不知怎么办）；③ 移动方向写反（应从左向右，R）。

### 题 2（中）：二进制奇数判定机——完整运行轨迹

**题干**：使用严格化走廊里设计的"二进制奇数判定机"（转移表见走廊），亲手走输入 `1011` 与 `1010` 的**完整格局序列**，每步标注依据；并核对最终接受/拒绝是否符合奇偶性。

**完整解答**（转移表同走廊：\(q_0\) 右扫，遇 ␣ 左移进 \(q_1\)，\(q_1\) 看个位 1 接受、0 拒绝）：

**输入 `1011`**（=11，奇数）：
| 步 | 状态 | 纸带 | 依据 |
|----|------|------|------|
| 初始 | \(q_0\) | \(\underline{1}\,0\,1\,1\,\square\) | 初始格局 |
| 1 | \(q_0\) | \(1\,\underline{0}\,1\,1\,\square\) | 读 1→R |
| 2 | \(q_0\) | \(1\,0\,\underline{1}\,1\,\square\) | 读 0→R |
| 3 | \(q_0\) | \(1\,0\,1\,\underline{1}\,\square\) | 读 1→R |
| 4 | \(q_0\) | \(1\,0\,1\,1\,\underline{\square}\) | 读 1→R |
| 5 | \(q_1\) | \(1\,0\,1\,\underline{1}\,\square\) | 读 ␣→L、进 \(q_1\) |
| 6 | \(q_{\mathrm{accept}}\) | \(1\,0\,1\,1\,\underline{\square}\) | 读 1(个位)→接受 |

**接受**（11 是奇数 ✓）。

**输入 `1010`**（=10，偶数）：
| 步 | 状态 | 纸带 | 依据 |
|----|------|------|------|
| 初始 | \(q_0\) | \(\underline{1}\,0\,1\,0\,\square\) | 初始格局 |
| 1 | \(q_0\) | \(1\,\underline{0}\,1\,0\,\square\) | 读 1→R |
| 2 | \(q_0\) | \(1\,0\,\underline{1}\,0\,\square\) | 读 0→R |
| 3 | \(q_0\) | \(1\,0\,1\,\underline{0}\,\square\) | 读 1→R |
| 4 | \(q_0\) | \(1\,0\,1\,0\,\underline{\square}\) | 读 0→R |
| 5 | \(q_1\) | \(1\,0\,1\,\underline{0}\,\square\) | 读 ␣→L、进 \(q_1\) |
| 6 | \(q_{\mathrm{reject}}\) | \(1\,0\,1\,0\,\underline{\square}\) | 读 0(个位)→拒绝 |

**拒绝**（10 是偶数 ✓）。

**反向核算**：两个例子的二进制值已手算核实（1011=11 奇、1010=10 偶）；机器第 5 步"读到 ␣ 左移"恰好落在最右输入符号（个位）上，个位 1→接受、0→拒绝，逻辑与结果一致。

**常见错误**：① 奇数机第 5 步**必须左移**（若右移会读到第二个 ␣ 而出错）；② 把"输入结束"（␣）当成个位判断——必须先左移回到个位再判断；③ 个位判断反了（0 是偶数应拒绝，1 是奇数应接受）。

### 题 3（难）：什么"不是"图灵机可计算的——直觉辨析

**题干**：老谟列出三样东西，问造物主哪个"不是图灵机可计算（可判定）的"：
(a) 判定一个二进制串是不是奇数；
(b) 判定一个**任意的**图灵机，在给定输入上是否**最终停机**（即"停机问题"）；
(c) 判定一个自然数是不是质数。
请逐一分析，并说出 (b) 为什么和 (a)、(c) 有本质区别。

**完整解答**：

- **(a) 可计算**：本章已构造出奇数判定机，对每个输入都停机并正确接受/拒绝。所以"判断二进制奇数"是**可判定**的。
- **(c) 可计算**：判断质数有确定的算法（如试除 \(\sqrt{n}\) 内的所有整数），可以写成图灵机，对每个输入都停机。所以"判断质数"**可判定**。
- **(b) 需要深入想**："给定一台图灵机 \(M\) 和一个输入 \(w\)，问 \(M\) 在 \(w\) 上最终是否停机"——这个问题是否可判定？**本章还不能下结论**（下一章将证明它**不可判定**）。这里的**直觉关键**在于：它的问题对象是"图灵机本身"——你要判定的是"这台机器会不会停下"，而机器可能**无限运行、永远不停**。这和 (a)、(c)（输入是有限的数据串，判定的过程总能扫完输入）有本质区别：停机问题的困难在于，**你无法通过"跑一遍看看"得到答案**，因为你不知道它什么时候才"算完"（它可能永远不算完）。

**答**：**(b)** 是最可疑、最可能"不是图灵机可计算"的——它正是下一章要证明的**停机问题不可判定**。本章先种下直觉：**"图灵机可算"只覆盖"总能停机并给出答案"的问题；而有些问题，本质上是"问机器自己会不会停"——这类问题把图灵机当成输入，会引出深刻的悖论。**

**常见错误**：① 误以为 (b) 也可计算，理由是"跑一遍看它停不停"——但"跑一遍"没法处理"永不停止"的情况（你永远等不到它停）；② 把"很难算"和"不可计算"混为一谈——质数判定很慢但可计算，(b) 是**原则上**算不出来；③ 没意识到 (b) 的输入是"图灵机+输入"这种**高阶对象**，这正是它特殊之处。

## 向导便签

> 这一章咱们干了什么：把"算"这个你天天用的词，从一团直觉钉成了一件能机械执行的东西——**图灵机**。你认识了它的七元组（\(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}\)）、四个零件（纸带+读写头+状态+规则表）、每步"读→写→移→变状态"的节奏；亲手造了"含 1 机"，亲手走了"奇数判定机"的完整格局序列；还摸到了那个地基级的信念——**Church–Turing 论题**。
>
> 钉死一句话：**"能算" = "图灵机能算"（Church–Turing 论题）；"可判定" = "存在一台对每个输入都停机且正确回答的图灵机"。** 变体（多带/双向/非确定）都等价，算不出来的墙只有一面。
>
> 记住：**这一章最大的转折，是问题对象从"有限的数据"跳到"机器本身"。** 我们已经能问"这台机器会不会停"这种把机器当输入的问题了——它既是"可计算"的边界，也是下一章那枚炸弹的引信。下一章，**可判定性与停机问题**——我们要亲手用反证法证明：**有一类问题，任何图灵机都算不出来。** 那将是全册第一次直面"算的边界"。

## 自测题

> 计算题须动笔完成，附完整解答自核；概念题用于检查理解。

**题 A（计算，易→中）：设计"串首为 1"的判定机**

设计一台图灵机，判定输入二进制串的**第一个符号是否为 '1'**（是则接受，否则拒绝）。写状态集、转移表，并走输入 `101` 的格局序列。

**完整解答**：只需一个扫描状态：起始 \(q_0\)，头对准首字符时：读 1 → 接受；读 0 → 拒绝。状态集 \(Q=\{q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}\}\)。转移表：\(q_0\) 读 1 → 写 1、R、进 \(q_{\mathrm{accept}}\)；\(q_0\) 读 0 → 写 0、R、进 \(q_{\mathrm{reject}}\)。（注意：这只判断首字符，无需扫描整串。）走 `101`：初始 \(q_0\) 头对准首字符 '1' → 读 1 → 进 \(q_{\mathrm{accept}}\)，**第 1 步即接受** ✓（首字符是 1）。

**题 B（计算，中）：奇数机走 `101` 与 `100`**

用本章奇数判定机的转移表（\(q_0\) 右扫→遇 ␣ 左移→\(q_1\) 看个位），完整走输入 `101` 与 `100` 的格局序列，并核对奇偶性。

**完整解答**：
- `101`（=5，奇数，应接受）：初始 \(q_0\) 头对准 '1' → 步1 读 1→R；步2 读 0→R；步3 读 1→R；步4 读到 ␣→L 进 \(q_1\)，头落第 3 格 '1'；步5 \(q_1\) 读 1（个位）→**接受**。5 是奇数 ✓。
- `100`（=4，偶数，应拒绝）：初始 \(q_0\) 头对准 '1' → 步1 读 1→R；步2 读 0→R；步3 读 0→R；步4 读到 ␣→L 进 \(q_1\)，头落第 3 格 '0'；步5 \(q_1\) 读 0（个位）→**拒绝**。4 是偶数 ✓。

**题 C（概念，检查理解）**

(a) 为什么 Church–Turing 论题是"论题"而不是"定理"？
(b) 什么是"可判定"？为什么它要求"对每个输入都停机"？
(c) 图灵机的变体（多带、非确定）能算的东西比原版多吗？为什么？
(d) 为什么说"判断二进制奇数"可计算，而"判断某图灵机在给定输入上是否停机"在下一章将被证明不可计算？两者的直觉差别在哪？

**完整解答**：
(a) 因为"直觉上可计算"没有形式定义，无法放进形式系统内证明；它靠"从未被推翻"的累积证据作为可计算性理论的地基被接受。
(b) "可判定"= 存在一台图灵机，对每个输入都停机，且属于 L 就接受、不属于就拒绝。要求"对每个输入都停机"是因为：若某输入上机器永不停机，就永远无法给出"否"的完整答案，只能算"半判定"。
(c) 不多。多纸带、非确定等变体都能被原版图灵机模拟，**接受的语言集合相同**；变体可能更快/更方便，但"能算的集合"没变（这正是 Church–Turing 论题坚固性的佐证）。
(d) "判断二进制奇数"的输入是**有限数据串**，判定过程总能扫完输入后停机；而"判断图灵机在给定输入上是否停机"的问题是问"机器会不会无限运行"，你无法通过"跑一遍"得到答案（它可能永不停止）——它把**机器本身**当输入，引向自指与悖论，这正是下一章停机问题不可判定的根源。
