## 二、P1 —— 明显缺陷

### P1-1：顶部导航「册次目录」下拉缺少册07
- **问题描述**：站点顶栏 nav「册次目录」下拉只列出册01–册06，**册07（图论与可计算性）无法从该入口进入**。侧边栏已完整包含册07（7章+答案速查页），首页 features 也提到 7 册，但顶栏下拉漏掉，用户若不开侧边栏将找不到册07。
- **复现路径**：打开任意页 → 顶部导航点「册次目录」→ 下拉只有 6 项，无「册07 · 图论与可计算性」。
- **根因**：`.vitepress/config.mts` 第 197–204 行的 `nav[1].items` 数组只有 6 个对象，漏写册07（对照第 111–125 行 sidebar 的 `books` 已含册07）。已在构建产物 `index.html` 的 `__VP_SITE_DATA__.themeConfig.nav` 中确认（仅 6 项）。
- **修复建议**：在 config.mts 第 203 行（册06 项）后追加：
  `{ text: '册07 · 图论与可计算性', link: '/册07-图论与可计算性/第01章-图的基础' }`
  （册07 第一章文件名是「第01章-图的基础」，与 sidebar 第 115 行一致。）

### P1-2：册07 数学公式中的空白符 `␣`（U+2423）KaTeX 无法渲染
- **问题描述**：册07第06章（图灵机）大量使用 `\text{␣}`、`\underline{␣}`、裸 `␣` 作为纸带「空白符」记号（核心概念），第08章（P与NP）亦同。KaTeX 不支持 U+2423 字符（无字符度量），构建时抛出 **20+ 条** "Unrecognized Unicode character '␣' ... No character metrics" 警告，渲染结果将是**缺失字形/错误框**，核心公式残缺。
- **复现路径**：`npm run build` 观察 KaTeX 警告；打开 册07第06章 第 307/312–313/326/340–346/354–360/411/423–426/441–460 行，数学单元格中 `␣` 显示为错误/缺失字形。
- **根因**：`册07-图论与可计算性/第06章-计算模型与图灵机.md` 等文件在**数学模式内**使用了 KaTeX 不支持的 `␣` 字符。KaTeX 的 `\text{}` 也不含该字符度量（已由构建警告证实）。
- **修复建议**：将数学模式内的 `␣` 替换为 KaTeX 支持的空白符记号，如 `\text{▫}`、`\square`、`\text{blank}`、`\text{\textvisiblespace}`（`\textvisiblespace` 为 KaTeX 支持的命令，能正确显示可视空白），或统一定义 `\newcommand{\blank}{\text{\textvisiblespace}}`。纯文本上下文（非数学）中的 `␣` 可保留。需复核第06/07/08章全部出现点。

## 三、P2 —— 体验优化

### P2-1：缺少 favicon，浏览器请求 favicon.ico 返回 404
- **问题描述**：`public/` 下只有 logo.svg 与若干 svg/png，未配置 `<link rel="icon">`；浏览器默认请求 `/math-foundation/favicon.ico` → 404。不影响页面功能，但控制台有 404 噪音、标签页无图标。
- **复现路径**：打开任意页，Network 面板可见 `favicon.ico` 404。
- **根因**：`.vitepress/config.mts` 的 `head` 未配置 favicon；VitePress 默认回退 `/favicon.ico`。
- **修复建议**：在 config.mts `head` 加 `<link rel="icon" href="/logo.svg">`（无 `/math-foundation/` 前缀，VitePress 自动 withBase；`public/logo.svg` 已存在）。

### P2-2：Windows 下 `vitepress preview` 后台进程不稳定，请求途中即掉线
- **问题描述**：在 Windows 用 `cmd /c npx vitepress preview` 后台启动时，服务在连续多次页面请求后进程中断（ERR_CONNECTION_REFUSED / RESET），导致 Playwright 批量抽查时部分页面表现为"无法加载/组件画布为空"。**这是测试环境问题，非站点本身缺陷**——在稳定服务器下组件渲染正常（见下文"已验证"）。
- **复现路径**：后台启动 preview → 连续访问 10+ 页面 → 中途服务断开。
- **根因**：后台进程被父会话回收 / 端口抖动；属本地 dev 环境稳定性问题。
- **修复建议**：开发期用 `node node_modules/vitepress/bin/vitepress.js preview`（绕开 npx shim）并前台保持；或使用 `vitepress dev` 热更新；CI/核查脚本建议在单进程内管理服务器生命周期。

### P2-3：侧边栏全局平铺 7 册，册01 展开其余折叠，窄屏浏览链路过长
- **问题描述**：sidebar 在所有页面都展示全部 7 册（每册 8–9 章 + 答案速查页），仅册01 展开。信息密度大，移动端体验一般（VitePress 抽屉默认按需展开，问题轻微）。
- **复现路径**：窄屏打开首页/任一章节，展开侧边栏可见 60+ 条层级。
- **根因**：config.mts 的 `sidebar` 为全局单组结构（`/` 下挂全部 books），未按路由分段。
- **修复建议**：可选，将 sidebar 按 `'/册XX-...'` 路由细分（每册只显示本册章节），提升专注度与加载量；若保持全局聚合，则维持现状即可（不影响功能）。
